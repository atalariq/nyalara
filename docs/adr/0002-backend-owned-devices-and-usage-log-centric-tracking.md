# Backend-Owned Devices And Usage-Log-Centric Tracking

For the mobile MVP, we decided that `users/{userId}/devices/{deviceId}` is backend-owned inventory and `users/{userId}/electricity_usages/{usageId}` is the canonical tracking record. Mobile may keep its existing screens, but core product data must move behind backend APIs: device inventory gets full CRUD, usage logs support create/read/update/delete, `device_breakdown` becomes the primary mobile input path, monthly summary and current streak recalculate synchronously on usage-log mutations, insights may remain stale until regenerated, and direct mobile Firestore writes are limited to `users/{userId}/preferences/main`. We chose this because it preserves the current UX, makes the backend service the source of truth, keeps devices useful as inventory and input presets, and avoids legacy root-collection authority without forcing a full UI rewrite days before the deadline.
